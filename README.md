# Road Pothole Detection

An offline computer-vision pipeline for detecting road defects in images and videos. The repository includes a Streamlit dashboard for running video inference, viewing an annotated result, and downloading track-level reports.

## What is implemented

- YOLO detector integration for four road-defect classes defined in `configs/data.yaml`.
- Shared confidence filtering, class-agnostic duplicate suppression, and annotation helpers.
- Clip-level tracking with the project’s custom `RoadTracker` implementation in `src/video/tracker.py`.
- Optional ResNet18 pothole-severity prediction using the included checkpoint, with a configurable bounding-box-area prior.
- Streamlit video workflow with a built-in smoke-test video or an uploaded video.
- Annotated MP4 output plus `tracks.csv` and `report.json` exports.
- Unit tests covering configuration, post-processing, tracking, dataset auditing, review utilities, and report-related helpers.

This is an offline prototype. Severity predictions are visual estimates and should not be used as a maintenance decision without human review.

## Repository contents

```text
configs/       Pipeline, detector, and tracker configuration
docs/          Project notes, experiment records, labeling guide, and reports
models/        Included detector and severity checkpoints
sample_data/   Small image/label sample used by local utilities
sample_videos/ Short videos for smoke testing
src/           Application and inference code
tests/         Automated tests
```

The runtime expects these model files to exist:

- `models/detector/best.pt`
- `models/severity/best_severity_model.pth` when severity classification is enabled

The repository does not contain the full training dataset. Dataset paths used for training must be configured locally.

## Setup

Python 3.10 or newer is required. Create an environment and install the repository dependencies:

```powershell
python -m venv .venv
.\\.venv\\Scripts\\Activate.ps1
python -m pip install -r requirements.txt
```

The dependency list is also declared in `pyproject.toml`; the commands above are the supported direct setup path for this repository.

## Run the Streamlit demo

From the repository root:

```powershell
python -m streamlit run src/app.py
```

Open the local URL printed by Streamlit. Leave **Use built-in smoke video** enabled to process `sample_videos/video_smoke_native_input.mp4`, or upload an MP4, AVI, MOV, or MKV file. Select **Analyze Video** to run detection and tracking.

The dashboard displays the annotated video and detected tracks. It provides downloads for:

- `annotated.mp4` — annotated video output
- `tracks.csv` — one row per retained track
- `report.json` — run metadata, configuration, and track summaries

Outputs generated by the app are written to a temporary directory for the current session. Command-line inference utilities write to the configured output directory under `configs/pipeline.yaml`.

## Configuration and architecture

`configs/pipeline.yaml` contains model paths, thresholds, image size, device selection, severity sampling interval, and output settings. Relative paths are resolved from the project root.

The Streamlit app calls `src/video/runner.py`. The runner loads the YOLO checkpoint, filters detections, assigns persistent IDs with `RoadTracker`, periodically samples pothole crops for severity inference, writes the annotated video, and serializes track summaries. The configured `video.tracker` path is retained as configuration metadata; the active runner uses the Python `RoadTracker` class.

## Tests and verification

Run the test suite with:

```powershell
python -m pytest
```

The test suite could not be executed in the audit environment because the available Python installation did not have `pytest` or the runtime dependencies installed, and the checked-in local virtual environment could not start its Python executable. No test result is claimed until dependencies are installed successfully.

The Streamlit smoke flow likewise requires the dependencies and model runtime to be installed. It has not been represented as a passing demo until that verification is completed.

## Known limitations

- Dependency versions are not pinned to exact releases.
- The full training dataset and training runs are not included.
- The included checkpoints are required for inference and are not reconstructed by the setup commands.
- Tracking is limited to a continuous video clip; GPS-backed identity across journeys is not implemented.
- Severity labels and predictions are prototype-level visual estimates with limited labeled data.
- No live deployment is included.
- No open-source license has been added.
